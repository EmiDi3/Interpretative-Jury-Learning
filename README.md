# Interpretative Jury Learning

Given an LLM's choices on [Moral Machine](https://moralmachine.mit.edu/) scenarios,
find a jury of **real survey participants** whose majority vote reproduces those
choices — and ask how big that jury must be and who is on it.

The mechanism is two-stage:

1. Train a model that predicts how *any* surveyed human would vote on *any*
   scenario (`MoralJuryDCN`, a Deep & Cross Network with a per-user embedding).
2. Use it to build a `users × scenarios` matrix of predicted votes, then search
   that matrix for a small subset of humans whose majority vote matches the LLM.

## Research questions

1. **Can** we find a jury whose majority vote reproduces the LLM's choices?
2. **How big** does that jury need to be?
3. **What demographics** characterize it — and are those conclusions stable?

`RESEARCH_PLAN.md` is the working plan of record, with the current status and the
open methodological problems. **Read it before running experiments.**

## Models

Three architectures share one `RunConfig`, selected with `cfg.model_type`:

- `"dcn"` — Deep & Cross Network with a per-user ID embedding (the main model)
- `"dcn_baseline"` — same network without the user embedding
- `"transformer"` — scenario-only Transformer encoder, extended with `[USER]` and
  `[GROUP]` prefix tokens

The saved `moral_jury_dcn.pth` was trained with Optuna trial #19
(`val_accuracy=0.7488`): `embed_dim=64`, `hidden_dim=512`, `num_cross_layers=4`,
`response_encoder_hidden=32`. Note these differ from the `RunConfig` defaults —
set them explicitly when loading the checkpoint, as notebook cell 26 does.

## LLM response data

10,000 scenarios each, generated by `06_llm_scenario_prompts.py` and answered by
three local models:

| File | Swerve | Stay | Unusable |
|---|---|---|---|
| `phi4.json` | 9,047 (90.5%) | 953 | — |
| `qwen2.5_14b.json` | 6,104 (61.0%) | 3,896 | — |
| `llama3.1_8b.json` | 4,782 | 2,588 | 2,630 (26.3% refused / other) |

Two things follow from this table, both of which the research plan treats as
blockers for any headline number:

- **Phi-4 is 90.5% swerve**, so an always-swerve jury already scores 0.905. Raw
  agreement is meaningless without the baselines in `RESEARCH_PLAN.md` Step 1.
- **Llama-3.1-8B has 26% unusable responses** (refusals and malformed answers)
  and needs a filtering decision before it can be used at all.

## Files not in git

Kept out deliberately (see `.gitignore`):

- `moral_jury_dcn.pth` (~120 MB) — over GitHub's 100 MB hard limit
- `moral_jury_baseline.pth` — regenerable training output
- `moral_machine.db`, `unique_scenarios.csv` — large source data, loaded from
  Google Drive at runtime by Section 0 of the notebook

Keep the checkpoints in the same Drive folder as `moral_machine.zip`.

## Running

Designed for **Colab with a GPU**. Section 0 clones this repo, mounts Drive, and
extracts the dataset. For local CPU work, set `cfg.sql_subset_size` to something
small (e.g. `100_000`) — the full dataset is ~4M rows and will not fit
comfortably in RAM.
